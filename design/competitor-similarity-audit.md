# Competitor / generic-dashboard similarity audit

Scope: `apps/client/src/app/{index,money,invest,settings,transactions,subscriptions,holdings,login}.tsx`, `components/AppShell.tsx`, `components/ui.tsx`, and the shared components each screen pulls in (`HoldingsList`, `MoneyLists`, `DebriefPanel`, `PortfolioChart`, `EventList`, `BrandMark`, `MarketSearch`, `PlaidLinkButton`, `AssistantDrawer`, `useConnectionSync`). Read directly from `StyleSheet.create` blocks — no running app was used.

Per the brief: **not** ranking by color usage. Ranked by how much each choice specifically produces the "this could be any fintech SaaS dashboard" impression, distinguished from ordinary table/form/list conventions that are fine to keep.

---

## Top offenders (highest contribution to the generic impression)

### 1. Login screen is a literal centered-hero + feature-card layout
**File:** `apps/client/src/app/login.tsx:60-129`, styles at `131-241`.

This is the exact pattern named as non-negotiable-to-reject in `.agent/skills/product-design/SKILL.md` ("centered hero + feature cards"). Structure: nav bar with wordmark → eyebrow pill-dot + label → giant headline with an accent-colored `<Text>` span (`headlineAccent`, line 78/186) → gray subheadline paragraph, max-width 480 → CTA button + reassurance caption → an adjacent bordered card titled "WHAT POSTED DOES" listing 4 rows of {icon-in-tinted-square, title, caption} (`features` array, lines 20-41; rendered 107-120). This is structurally identical to a Stripe/Linear/Vercel marketing one-pager and to virtually every shadcn/Tailwind "hero + feature grid" template in the reference repos. The feature copy itself ("Banking + investing, one view", "Ask Posted") reads as generic SaaS marketing bullets, a different voice from the literal, numbers-first register used everywhere else in the app (e.g. "NET CASH POSITION", "MSPR"). This is Posted's only real first-impression surface (per SKILL.md, the one place a bolder moment is earned) and it currently is the most templated screen in the codebase, not the most distinctive one.

### 2. One bordered/rounded/shadowed "panel" is the container for literally everything
**Definition site (repeated near-verbatim, not shared as a component):** `index.tsx:288-295`, `money.tsx:405-412`, `invest.tsx:282-290`, `settings.tsx:600-607`, `transactions.tsx:142-149`, `subscriptions.tsx:127-134`, `holdings.tsx:80-87`, plus `DebriefPanel.tsx:117-125` and `AssistantDrawer.tsx:86-101` (floating variant). Same shape every time: `borderWidth:1, borderColor: colors.line, backgroundColor: colors.surface, borderRadius: radius.lg, overflow:'hidden'` plus the shared `cardShadow` token (`theme/tokens.ts:51-57`, spread in 20 places per repo-wide grep).

This is exactly the non-negotiable-to-reject "everything in a bordered rounded card" default, and it is not a stylistic accident — it is the *only* structural idea in the visual system. A stock table (holdings), an account list, a transaction feed, a settings row group, an AI-generated debrief, and a floating chat drawer all use the identical shell. Nothing on screen currently has a container treatment that couldn't be swapped onto a generic CRM or PM tool. This is one of the two or three biggest levers for a redesign: differentiate the *shell* per content type (a table doesn't need the same wrapper as a chat drawer) rather than reusing one soft-shadow card everywhere.

### 3. `SectionHeader` + panel + row-list composition is repeated identically ~46 times
**Definition:** `components/ui.tsx:7-25`. **Usage count:** 46 call sites across `app/`.

Every section on every screen, with no variation: panel wrapper → `SectionHeader` (bold 15px title, small gray caption, optional right-aligned text link/button) → a list of rows. This is the RN reimplementation of shadcn's `Card` + `CardHeader` + `CardContent` / the AdminLTE "card with header and body" convention — the literal shared DNA the brief flags across generic dashboard templates. Having one primitive for this is reasonable engineering; the problem is that it's used with zero variation regardless of what the section actually is (compare "Portfolio performance" chart panel at `index.tsx:165-174` to "Accounts" list at `index.tsx:175-204` to "Recurring charges" at `money.tsx:158-165` — same header treatment, same caption placement, same optional arrow-link action, just different children).

### 4. Metric-row → two-column-panels page shape, repeated on every primary screen
**Where it appears:**
- `index.tsx:105-247` — metrics row (109-162) → two-column (chart + accounts, 164-205) → two-column (holdings + feed, 207-234) → sidebar debrief.
- `money.tsx:107-166` — metrics row → two-column (activity + accounts) → two-column (transactions + subscriptions).
- `invest.tsx:90-176` — hero block → metric row (107-136) → stacked panels (holdings, then accounts).
- `transactions.tsx:63-81`, `holdings.tsx:34-48`, `subscriptions.tsx:50-55` — hairline "summary tile" row followed by one or two panels.

This is precisely the "KPI row + two even panels" shape that recurs across Mint/Copilot/Monarch overview pages, generic admin dashboard templates, and the shadcn "dashboard-01" example equally. It is not wrong to put the most important numbers first — but as implemented, the shape is interchangeable: nothing about "Portfolio performance chart | Accounts list" as a side-by-side pairing is more inherently Posted than "Chart | Accounts" would be for any brokerage clone. This — combined with #2 and #3 — is the layout DNA a "swap the logo" test would catch fastest. Genuine differentiation would mean picking, per screen, a structure that follows from the specific task (e.g., a scrub-driven ledger/tape reading order rather than a card grid), not a lighter reflow of the same three-zone template.

### 5. Sidebar/bottom-nav chrome is stock admin-template navigation
**File:** `components/AppShell.tsx:176-224` (desktop sidebar), `335-358` (mobile bottom bar), `259-312` (avatar + dropdown user menu).

The Money/Investing grouping itself is genuinely Posted-appropriate IA (see below, this part is fine). The *chrome* is not: a fixed-width dark sidebar with small-caps section labels (`navLabel`, 387-394), nav rows with a colored left-rail indicator for the active item (`navIndicator`/`navIndicatorActive`, 404-405), and a circular initials avatar that opens a dropdown menu (`avatar`, 448-455; `userMenu`, 465-481) is the default admin-dashboard nav found in essentially every reference template (compare directly to the shadcn/admin examples in the scratchpad refs). Nothing about the visual treatment signals "trading terminal" over "generic SaaS back office."

## Findings that are ordinary/conventional and should NOT be treated as unoriginality

- **Row-based lists for holdings/transactions/accounts** (`HoldingsList.tsx:77-136`, `MoneyLists.tsx` throughout). Icon-or-badge + name/meta stacked + right-aligned numeric column(s) is how ledgers and statements are read; this is the correct call for a "trading-terminal register," not a generic pattern to avoid. Forcing these into a card grid instead would be a regression, not an improvement — the SKILL.md itself names "not a card grid of holdings, a table commands scanning" as the right screen-specific rejection.
- **Search/filter affordances** (`transactions.tsx:114-126` filter chips, `holdings.tsx:49-64` inline search box, `MarketSearch.tsx`). Rectangular selectable chips and a bordered search box with a leading icon are unremarkable, functional conventions — not the "pill-shaped controls everywhere" default the brief flags (checked: `radius.pill` is used in exactly one place app-wide, `StockPriceChart/IndicatorToolbar.tsx:236`, a legitimate toggle-group case). Fine to keep.
- **SMS linking form** (`settings.tsx:449-513`). Plain bordered `TextInput` + solid button, phone then 6-digit code. No pill inputs, no floating-label affectation, no unnecessary novelty. This is appropriately boring for a security-adjacent form; not a mark against originality either way.
- **Loading/Error/Empty states** (`ui.tsx:69-92` `LoadingState`/`ErrorState`; `MoneyLists.tsx:68-74` transaction empty state). Spinner+label, icon+message+retry, and "No transactions match these filters." are minimal and utilitarian. Not a differentiator, but also not evidence of templated design — this category is fine to leave mostly as-is per the brief's own carve-out for ordinary conventions.
- **`DemoBanner`** (`ui.tsx:54-67`, used in `index.tsx:107`, `money.tsx:103/189`, `invest.tsx:71`). The demo-vs-live distinction is genuinely load-bearing for this specific product (one person with real Plaid/Schwab connections who needs to know if they're looking at sample data). Correctly domain-specific, not a generic banner pattern.
- **Sync-freshness indicator** ("Last synced Xm ago" + small live dot: `index.tsx:198-203`, `money.tsx` accounts panel, `invest.tsx:95-104` hero footer) and **`useConnectionSync`'s auto-sync-when-stale + manual-sync-mutation model** (`lib/useConnectionSync.ts`). This is exactly the kind of signature interaction SKILL.md calls out as Posted-specific (real provider sync state) versus a generic "last updated" caption. Good — keep and, if anything, make more visually prominent since it's currently a small caption + 6px dot that barely reads as a feature.
- **Privacy-mode eye toggle** (`index.tsx:65-74`, `money.tsx:60-69`, `invest.tsx:50-60`). Masking real balances is a genuinely relevant feature for someone who might have the app open on a shared screen — not a generic dashboard trope. The *execution* is flagged separately below (touch target size, three near-identical copies).

## Component structure

- **Metric-card grid uses a 1px hairline-gap grid on a colored background rather than gapped, individually-shadowed cards** — `index.tsx:268` (`metrics: { ..., gap: 1, backgroundColor: colors.line }`), same pattern in `money.tsx:395`, `transactions.tsx:136`, `subscriptions.tsx:114`, `holdings.tsx:75`. This is a genuine positive: it reads more like a bank-statement/ledger rule than a "bento grid of cards," and is one of the few places the app currently does something other than the default rounded-shadow-card. It is not leveraged as an explicit signature anywhere else in the system, though — it's a happy accident of the metric row specifically, not a deliberate motif carried through headers, tables, or the chat drawer.
- **Icon treatment is a uniform tinted-square "chip" regardless of content type**: `width/height: 34-38`, `backgroundColor: colors.<x>Soft`, centered icon — `settings.tsx:609-615` (provider mark), `693` (integration icon), `699` (setting icon); `invest.tsx:204-210` (insider link icon); `MoneyLists.tsx:189-195` (account icon), `214` (transaction icon), `238` (subscription icon); `AssistantDrawer.tsx:127-134` (header icon); `money.tsx:386-387,392` (mobile metric/quick-action icons). `lucide-react-native` itself is an appropriate, neutral icon choice (not a giveaway on its own) — the issue is that a bank-connection icon, a chevron, a receipt, and the AI-assistant sparkle all sit in the exact same visual container, so nothing reads as purposefully designed for what it represents; every icon is dashboard iconography, not Posted iconography.
- **Connection rows in Settings** (`settings.tsx:216-258` money connections, `292-339` investing connections) are a reasonable, utilitarian settings-list pattern (identity block + sync/unlink actions or a DEMO badge) — this is fine and not a mark against originality; the provider-status badges (`READY`/`SETUP`, `264-279`, `355-368`) are a nice, real, functional touch specific to Posted's own backend-configuration state.
- **`DebriefPanel`** (`components/DebriefPanel.tsx:117-125`) is the one panel with a distinguishing accent (`borderTopWidth: 3, borderTopColor: colors.ink`) instead of the plain hairline border everyone else gets — a small, correct attempt at a signature element for "the one AI-written thing on this screen," but it's subtle enough (a 3px top rule) that it doesn't read as different from the rest of the two-column-panel shape it sits inside (finding #4).

## Typography and spacing (`theme/tokens.ts`)

- `tokens.ts:66-74` declares a 7-step type scale (`micro:10` … `display:38`) and `tokens.ts:33-41` declares a 7-step spacing scale (`xxs:4` … `xxl:48`). **These are used almost nowhere.** Repo-wide grep: the type scale (`type.*` / `typeTokens.*`) is referenced 5 times, all in `login.tsx`/`login/callback.tsx`; the spacing scale (`spacing.*`) is referenced 17 times, also all in `login.tsx`. Every other screen (`money.tsx`, `index.tsx`, `invest.tsx`, etc.) hardcodes literal pixel values directly in `StyleSheet.create` — a sample from `app/*.tsx` alone turns up font sizes of 7, 8, 9, 10, 11, 12, 13, 14, 15, 17, 18, 19, 22, 23, 24, 27, 30, 31, 34, 36, 40, 56 as one-off numbers, many with no relationship to the declared scale. This means there is a design-system intent (tokens.ts) that the actual screens don't follow — the type/spacing system exists on paper but the shipped screens were each hand-tuned independently. This is a meaningful, verifiable finding distinct from "looks like a competitor": it's why the app currently doesn't have a legible, consistent rhythm of its own to point to as a signature (the "token test" in SKILL.md — do token names belong to Posted's world — currently fails not because the names are generic, but because most screens bypass the tokens entirely).
- Where type *is* used consistently, it leans correctly domain-flavored: small-caps, wide-letter-spacing labels ("NET CASH POSITION", "TOTAL RETURN", "ATTENTION NEEDED") rather than generic "Revenue/Growth/Users" SaaS metric language, and tabular-nums applied consistently to money values (e.g. `index.tsx:279-282`, `HoldingsList.tsx:174-192`). This is a genuine positive worth preserving explicitly in the redesign, independent of fixing the token-usage gap above.

## Interaction patterns

- **Privacy-mode eye toggle** is implemented identically three separate times as inline JSX rather than a shared component (`index.tsx:65-74`, `money.tsx:60-69`, `invest.tsx:50-60`), each a 38×38 bordered square button. Below the 44×44 WCAG touch target SKILL.md already flags as a floor requirement, and duplicated instead of factored into `ui.tsx` alongside `ActionButton`. Same 38×38 undersized pattern recurs at `settings.tsx:610`, `invest.tsx:185/205`, `insiders.tsx:768`. This is a real, fixable inconsistency, not a "looks like a competitor" issue per se, but it's evidence the icon-button treatment was copy-pasted screen to screen rather than designed once.
- **Sync interactions** (`ActionButton` "Sync now"/"Sync all", `ui.tsx:27-52`) are a plain solid rectangular button with icon+label — appropriately restrained (not a pill, not a gradient CTA). Fine.
- **Pull-to-refresh** (`AppShell.tsx:314-330`, `RefreshControl` wired to `onRefresh`/`refreshing` props threaded from each screen) is standard RN/OS-native behavior — this is a case where matching platform convention is correct, not a genericness concern.
- **No motion/transition system exists.** Grep across `app/` and `components/` turns up no `Animated`/`react-native-reanimated` usage; state changes (pressed states, sync pending, privacy toggle) are handled with instant style swaps (`actionPressed`, `unlinkButtonPressed`, opacity flips) with no timing. SKILL.md calls for ~150ms micro-interaction / ~200ms panel-transition motion tied to state changes (sync completing, privacy mode toggling, assistant drawer opening/closing) as a non-negotiable engineering floor — currently absent everywhere, including the assistant drawer's open/close (`AppShell.tsx:361-368`) which just conditionally mounts/unmounts with no enter/exit transition. This isn't "looks like a competitor" so much as "currently reads as inert" — worth fixing regardless of the originality work.

## Onboarding (Plaid/Schwab Link)

- Settings screen treats bank/brokerage linking as inline rows inside the same generic `panel` (`settings.tsx:206-284` banking, `286-402` investing) with a `PlaidLinkButton`/`PlaidInvestmentLinkButton`/Schwab OAuth button at the bottom of each panel. Functionally sound (readiness badges showing backend config state are a nice, real touch, `settings.tsx:274-279,355-368`), but visually it's indistinguishable from a generic "integrations" settings page in any SaaS product — again inherits finding #2/#3's genericness rather than introducing new issues of its own.
- `PlaidLinkButton.tsx:85-106` is a single full-width dark button + helper caption + inline success/error text — plain and functional, not a source of "generic SaaS" impression on its own; the helper copy ("your banking credentials stay with Plaid") is appropriately reassuring and specific.

## Copy and tone

- Data labels and section captions are consistently domain-precise and in Posted's own voice: "SEARCHABLE ACTIVITY ACROSS ACCOUNTS" (`transactions.tsx:62`), "Detected from posted activity" (`subscriptions.tsx:52`), "Evidence, not a provider label" (`subscriptions.tsx:67`), "Apple Pay does not expose a universal cross-merchant subscription ledger" (`subscriptions.tsx:75`). This is good, specific writing that a generic fintech template would not produce — worth explicitly preserving.
- Login screen copy breaks this voice: "Banking + investing, one view", "no more switching apps", "Takes ten seconds. We only ever store your name and email." (`login.tsx:20-41,100-102`) reads as generic SaaS landing-page marketing copy, consistent with finding #1 — the tone shift between login and the rest of the app is itself a tell that login was designed to a different (more generic) template than the interior screens.

## Responsive behavior

- `money.tsx` has a genuinely distinct mobile composition (`MobileMoneyOverview`, `173-275`): a dark hero card with net cash + monthly commitments, a two-tile spend/income row, three quick-action tiles, then stacked panels in a different order than desktop. This matches SKILL.md's requirement for real mobile-specific design, not reflow — good, keep as the model to extend elsewhere.
- By contrast, `transactions.tsx`, `holdings.tsx`, and `subscriptions.tsx` mostly just toggle a `compact`/`mobile` boolean that trims a column or moves the search box (`transactions.tsx:74-113`, `holdings.tsx` has no mobile variant at all), rather than rethinking the composition the way `money.tsx` does. This is closer to "reflow the desktop grid to one column," which SKILL.md explicitly warns against — worth flagging as inconsistent execution of an otherwise-correct principle (money.tsx) rather than a wholesale failure.
- `index.tsx:28-31` redirects non-web platforms straight to `/money` rather than attempting to cram the two-column desktop dashboard + sidebar debrief onto a phone. Reasonable stopgap given real device constraints, but it does mean the "portfolio overview" identity (the app's primary surface, per SKILL.md's domain snapshot) currently has no native mobile expression at all — worth a decision in the redesign about whether that's intentional long-term or a gap to close.

## Summary ranking (most to least load-bearing for the generic impression)

1. Universal bordered/shadowed "panel" as the only container shape (finding #2) — combined with...
2. ...the identical `SectionHeader`+panel+list composition used 46 times with no variation (finding #3), and...
3. ...the repeated metric-row-then-two-column-panels page shape on every primary screen (finding #4). These three together are the actual "shared DNA" the brief is worried about — fix these and most of the "swap the logo" risk goes away.
4. Login screen's centered-hero-plus-feature-cards structure (finding #1) — narrower in scope (one screen) but the single most obviously templated individual screen, and the one place first impressions are formed.
5. Generic sidebar/bottom-nav chrome (finding #5) and uniform icon-chip treatment — real but smaller contributors once 1-3 are addressed, since IA and icon choice are already reasonable; only the visual execution is stock.
6. Type/spacing token system declared but unused outside login.tsx — not itself a "looks like a competitor" issue, but the reason the app doesn't yet have a legible rhythm of its own to contrast against the generic default.
